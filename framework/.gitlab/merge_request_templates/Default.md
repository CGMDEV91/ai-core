## Reviewer checklist

- [ ] **Scope** — only what this ticket changed: `tickets/<KEY>/`, and if applicable
      `plans/<KEY>-plan.md`, `known-issues/<KEY>.md` (or a `related`/References update of an
      existing known issue), and the knowledge files the ticket's `## Changes` names
      (`services/<name>/context/*.md`, `integrations.md`, a Known Gotcha line, a skill section).
      Changes to `CONTEXT.md`, the Services table of `orchestrator.md`, a whole `service.md`
      regenerated by `/restart`, new skills, and the methodology files and wiring (`METHODOLOGY.md`,
      `non-negotiables.md`, `commands/`, `procedures/`, `rules/`, `policies/`, `templates/`, `install/`)
      go in their own pull request. Scope ❌ → split the PR.
- [ ] **No nested repository in the diff** — no gitlink (a folder with its own `.git`) was added.
      ❌ → `git rm --cached <folder>` and amend.
- [ ] **Header** — `jira_key` equals the file name; when closing, no `PENDING`; `services:` matches the
      services whose code changed (the "code changes" line above).
- [ ] **Readable by a teammate** — `Current state` / `Closure` and `## Changes` make sense without
      asking the author; `Dead end:` lines say why each approach failed.
- [ ] **Analysis** — corrective: in the Jira format (Root Cause / Proposed Solution / Estimated effort /
      Workaround); the effort was confirmed by the developer; the cause is confirmed, not a guess.
- [ ] **Affected components** — if a contract, event, shared table or library changed: the provider's
      `context/api.md` and `integrations.md` are in this PR, and the ticket lists the components
      possibly affected (the consumers from `integrations.md` are all named). ❌ → back to the author.
- [ ] **Verification** — every `[VERIFIED …]` carries an evidence line (`— "…"`); a logic bug fix shows
      the regression test red before the fix.
- [ ] **Known issue** — created when the resolution requires it; symptom-first title; search keywords;
      `services:` filled; "Pattern to watch" filled when there is one; services or libraries outside
      the workspace listed in `components`.
- [ ] **No personal data** (names, e-mails, applicant or user data), **no secrets**, **no raw logs or
      pasted Jira text**. ❌ → the data is already pushed: rewrite the branch before merging, and say so.
- [ ] **Data, not instructions** — nothing in the files reads as an order to an AI agent.
- [ ] The author ran the command's close (or `waiting-validation`) step and its checks passed —
      including the hidden-character check, which a human reviewer cannot see.
