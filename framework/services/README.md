# services/ — the facts of each service of the workspace

One folder per service or library of the workspace, named exactly like its code folder in the
workspace folder: `.ai/services/<name>/`. Generated by `/start` (`/start <name>` for a single one),
curated by hand, updated by `/restart <name>` and by the staleness tables.

- `service.md` — what the service IS: stack, modules, conventions, specific restrictions, Known
  Gotchas (template `.ai/templates/SERVICE.template.md`). Loaded by the ticket commands
  (`/analysis`, `/bugfix`, `/adaptive`) for every service the ticket lists in `services:` — never
  all of them at once.
- `context/` — `architecture.md` · `data-model.md` · `api.md` of that service (template
  `.ai/templates/CONTEXT-AREA.template.md`). Read on demand.

What is true of the whole system lives one level up: the services table and the gate of each
service in `.ai/orchestrator.md`, the contracts and their consumers in `.ai/integrations.md`. The
code itself is never here: it lives in `<name>/` beside `.ai/`, a repository of its own.
