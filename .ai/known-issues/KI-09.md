# A Drupal project with the docroot at the repository root gets no hook signatures and the wrong core path

## Symptom

On a ddev project with `docroot: ""` (`core/`, `index.php` and `lib/` at the repository root) `detect` writes `apiRoot: web`; the API index is empty, `where --kind hook` finds nothing and the orchestrator shows no Drupal version.

## Root cause

`detect.ts` looked for `core/lib/Drupal.php` only under `web/`, `docroot/` and their sub-folders, and defaulted to `web`.

## Fix / solution

`apiRoot` is `"."` when `core/lib/Drupal.php` is at the root. `apiindex.ts` then scans only `core/`, `modules/` and `profiles/` (never `vendor/` or `node_modules/`), and the orchestrator prints `core`. Test: `tests/stacks.test.mts` (docroot at the repository root).

## Pattern to watch

Any code that joins `apiRoot` with a path must accept `"."`. Any scan from a docroot that is the repository root must name its folders.

## Files

- `framework/scripts/lib/detect.ts` — `detectService()`
- `framework/scripts/lib/apiindex.ts` — `build()`
- `framework/scripts/lib/orchestrator.ts` — `drupalFacts()`
