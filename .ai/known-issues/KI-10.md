# Two methodology repositories write into one .ai and one machine

## Symptom

After moving a project from the old methodology repository to ai-core, `.ai/scripts` kept `METHODOLOGY-OWNED` and `AI-CORE-VERSION`, and `guidelines.local.json` sat beside `framework.local.json`. Running the old repository's installers afterwards downgraded the project to 3.3 (`.ai/install/VERSION` 3.3, doctor: wiring version older), added a second `ai-framework` block to `.bashrc` that won over ai-core's, and rewrote the same 15 commands, 5 agents and `.ai-methodology.json` of opencode and Claude Code.

## Root cause

Both repositories use the same names: the command stubs, the agents, the manifest, `install-ai-framework` / `update-ai-framework`, the folder `.ai`. Neither knows about the other, and a copy never deletes.

## Fix / solution

ai-core's `install.sh` / `install.ps1` remove the files of the earlier set-up on every update (`scripts/METHODOLOGY-OWNED`, `scripts/AI-CORE-VERSION`, and the old record), `install-commands.sh` replaces the old shell block, and `update-ai-framework` switches a project recorded with another source to ai-core. Test: `tests/claude.test.mts`. The old repository's installers are not run on a machine or a project that uses ai-core.

## Pattern to watch

Any new file a framework version stops shipping must be added to the retired list in both installers.
